# Sprint 8 XP, Levels and Saving Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enemies drop XP gems, XP raises a permanent wizard level (1 to 20) that is saved between runs, and each level from 2 to 20 gives its reward: stats and slots right away, starting-spell rewards at the next run start.

**Architecture:** A `LevelTrack` resource holds the 19 `LevelReward`s (levels 2 to 20), the XP curve and the buff pool. A `PlayerProfile` (total XP plus the buff picked for each buff reward) is stored by a static `SaveGame` as versioned JSON. `StatBonuses` sums the stat rewards, and one `Player.apply_stat_bonuses` computes speed, health and spell mana from the player's base values, so applying twice is harmless. A `RunProgress` component on the Player turns collected XP into level-ups. A static `StartingBuffs` and `RunStart` rebuild the starting spells with their buffs at the start of a run. XP gems are passive pickups collected by the existing `PickupCollector`.

**Tech Stack:** Godot 4.7.2, typed GDScript, GUT 9.7.1, Compatibility renderer. Existing code in `scripts/`, `scenes/`, `resources/`, `tests/`.

**Spec:** `docs/sprints/sprint-8-design.md` (approved, with level 1 as the starting level and no reward). Also `docs/sprints/sprint-7-design.md`, `CLAUDE.md` and `technical-design.md`.

## Global Constraints

- Commands run with the venv active. Any Python is `venv/bin/python` (never bare `python3`). Test command: `godot --headless -s addons/gut/gut_cmdln.gd -gdir=res://tests -gexit` (add `-gselect=<file without .gd>` for one file). Run `godot --headless --import` after adding or renaming a `class_name` script. On macOS use `sed -i ''`, prefer the Edit tool for multi-line edits, and zsh does not word-split unquoted variables.
- Work on branch `sprint-8-xp` (already cut from `main`, design committed). Commit trailer: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. New files get their `.uid` committed (`git add -A`).
- Delete files only by literal full path (no variables or wildcards in `rm`). Scratch files go in the session scratchpad, never installed into home folders.
- Typed GDScript, snake_case/PascalCase/UPPER_SNAKE_CASE, one responsibility per script, **no new autoloads**, Input Map actions only (device -1 on every event). Don't name a parameter `position` in a `Node2D` subclass or a local `owner`. World scenes keep every `Control` at `mouse_filter` IGNORE (`tests/test_world_input.gd`). In headless GUT runs pointer events never reach `_unhandled_input`, so touch behaviour is proven with a real-window script, not a headless test.
- **No code branches on a level number or a buff id.** Rewards, the XP curve, the buff pool and the second spell are data on `LevelTrack`. Bonuses are never written into a shared `SpellData` or `EnemyData`.
- **Tests never touch the real save.** `SaveGame` functions take a path. Tests use a folder inside `res://.godot/save_tests/` (`.godot` is git-ignored), which each test creates and removes (`ProjectSettings.globalize_path`). `Main` has `@export var save_path: String = SaveGame.DEFAULT_PATH`, and an empty string means "do not load or save". Every test that instantiates `main.tscn` sets `save_path` before adding it to the tree (the plan names them in Task 8).
- Existing behaviour must not change for a fresh profile at level 1: the player has 1 slot, base speed, base health, no mana bonus, and Fire Missile unmodified.
- Mana still never regenerates. `SpellInstance` stays the only owner of mana.
- **Level curve.** The XP needed to reach level L (L from 2 to 20) is the sum, for k from 2 to L, of `first_cost + cost_step * (k - 2)`, with `first_cost = 30` and `cost_step = 20`: level 2 at 30, level 3 at 80, level 4 at 150, level 20 at 3990. Level 1 is at 0. The level never exceeds `max_level()` (20) and XP keeps counting.
- **Rewards** (`LevelTrack.rewards`, index 0 is level 2). Stat amounts are fractions of the base value.

  | level | kind | amount | spell_index |
  |---|---|---|---|
  | 2, 6, 11, 16 | SPEED | 0.08 | |
  | 3, 8, 13, 18 | HEALTH | 0.20 | |
  | 4, 9 | MANA | 0.15 | |
  | 5, 10, 15, 20 | SLOT | | |
  | 7 | RANDOM_BUFF | | 0 |
  | 12 | CHOSEN_BUFF | | 0 |
  | 14 | SECOND_SPELL | | (`spell` = `sea_cone.tres`) |
  | 17 | RANDOM_BUFF | | 1 |
  | 19 | CHOSEN_BUFF | | 1 |

  `LevelReward` also has a `description: String` (the toast text, for example "Faster movement", "Slot 2 unlocked", "Starting spell: random buff", "Starting spell: choose a buff", "Second starting spell: Sea Cone").
- **Applying rewards.** `Player.apply_stat_bonuses(bonuses, heal_difference)` sets speed to `base_speed * (1 + sum of SPEED)`, max health to `base_health * (1 + sum of HEALTH)` (when `heal_difference` is true the current health rises by the amount the maximum rose, otherwise current becomes the maximum), and the loadout's mana bonus to the sum of MANA. Slots: a run starts with `1 + the SLOT rewards up to the level`, and a mid-run SLOT reward calls `unlock_next()`.
- **Spell mana bonus.** Each `SpellInstance` has a `max_mana_bonus` fraction. Its pool is `data.max_mana * (1 + bonus)`. When the bonus rises, current mana rises by the same amount. A new instance created by `equip` starts full at the bonus pool. The cost per cast does not change.
- **Starting-spell buffs.** The profile stores `buff_picks`: reward level to buff scroll id. A BUFF reward (RANDOM or CHOSEN) reached with no pick is "unresolved". Random ones are rolled from `LevelTrack.buff_pool` (five scrolls, Additional Base is not in it) when the level is reached or, for any left over, at run start. Chosen ones are owed to the pick screen at run start. A buff already at its `max_stacks` for that spell is not offered or rolled. The spell for a reward is `LevelReward.spell_index` (0 is the first starting spell, 1 is the second). `SpellBuilder.with_buffs(spell, buffs)` returns a copy with the buffs folded in by the same rules as crafting.
- **Save.** JSON in `user://save.json`: `{"version": 1, "total_xp": int, "buff_picks": {"7": "buff_damage", ...}}`. Written to `<path>.tmp` then renamed over the old file. Load: missing file gives a fresh profile. A file that is unreadable, not a dictionary, has a different `version`, or has a wrongly typed field is renamed to `<path>.bak` and a fresh profile is returned. Unknown buff ids are skipped by `StartingBuffs`, not by the save.
- **XP gems.** `EnemyData.xp_reward` (plain 5, Fire 4, Thunder 4, Sea 6, Land 10). `XpDropper` caps the gems at 150, and at the cap a new gem's value is added to the oldest gem.
- Perf gate: `stress_test.tscn --enemies=300 --seconds=8 --drops` (now dropping gems too) stays at or above 60 fps, and is no worse than 10% below the Sprint 7 baselines in `development-log.md`.

## Review Focus

- A corrupt, empty, wrong-shaped, wrongly typed or newer-version save never crashes the game, is kept as `.bak`, and gives a fresh profile. Pinned in Task 2.
- A huge XP gain (several levels at once, past level 20, zero or negative amounts) applies every reward exactly once, in order, and never goes past level 20. Pinned in Task 4.
- A restart (the scene reloads) never applies a bonus twice: `RunStart` and `apply_stat_bonuses` give the same health, speed, slots and spells however many times they run. Pinned in Tasks 4 and 5.
- XP is never lost: at the gem cap the value is merged, and an XP total survives save and load exactly. Pinned in Tasks 2 and 3.
- A chosen buff that was not picked (the game was closed first) is asked again next run, the pick screen never offers a buff at its stack cap, and a pool with nothing left to offer skips the pick instead of hanging. Pinned in Tasks 5 and 6.

### Task 5: Starting-spell buffs and the run start

**Files:**
- Create: `scripts/progression/starting_buffs.gd`, `scripts/progression/run_start.gd`, `tests/test_starting_buffs.gd`, `tests/test_run_start.gd`
- Modify: `scripts/crafting/spell_builder.gd`, `tests/test_spell_builder.gd`

**Interfaces:**
- Consumes: Tasks 1, 2 and 4, `SpellBuilder`, `BuffEffect`.
- `SpellBuilder.with_buffs(spell: SpellData, buffs: Array) -> SpellData`: a copy of `spell` (every exported field, plus `buff_stacks` copied by value) with each buff folded in by the same rules `_apply_buffs` uses. It starts from the copy's own `copies`, `vulnerability_scale`, `ignores_resistance` and `buff_stacks`. Returns null if `spell` is null or any entry is not a Buff scroll with an effect. The original is never changed. The copy's `display_name` is the original's.
- Produces `StartingBuffs` (`RefCounted`, all static):
  - `unresolved_levels(profile, track, level: int, kind: LevelReward.Kind) -> Array[int]` (the reward levels up to `level` of that kind, ascending, that have no pick in the profile).
  - `settle_random(profile, track, level: int, rng) -> Array[int]` (rolls every unresolved RANDOM_BUFF reward up to `level` from the options for its spell and stores the pick; returns the levels it rolled; a reward with no option left stays unresolved and is not returned).
  - `options_for(profile, track, reward_level: int) -> Array[ScrollData]` (the `buff_pool` scrolls whose stack count among that spell's existing picks is below `max_stacks`, where 0 means unlimited).
  - `buffs_for_spell(profile, track, level: int, spell_index: int) -> Array[ScrollData]` (the picks of rewards up to `level` aimed at that spell, in level order, resolved through `buff_pool`; ids not in the pool are skipped).
- Produces `RunStart` (`RefCounted`, static): `prepare(player: Player, profile: PlayerProfile, track: LevelTrack) -> void`.
