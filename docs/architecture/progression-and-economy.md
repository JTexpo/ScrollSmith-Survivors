# Progression and economy

XP, levels and saving, Gold and equipment, and potions. Moved word for word from `CLAUDE.md`, one `##` section per sprint. Sections name each other (for example "see Obstacles"); find them in this folder (the index is in `CLAUDE.md`, "Where the detail lives").

## Progression (Sprint 8)

- XP and level are **permanent**. Everyone starts at level 1, which gives nothing. `LevelTrack` (`resources/progression/level_track.tres`) holds the XP curve, the 19 `LevelReward`s for levels 2 to 20 (SPEED, HEALTH, MANA, SLOT, RANDOM_BUFF, CHOSEN_BUFF, SECOND_SPELL) and the `buff_pool`. All of it is data, and no code branches on a level number or a buff id. The level is always computed from `PlayerProfile.total_xp`.
- **Saving.** `PlayerProfile` (total XP, Gold, owned and equipped items) is written by the static `SaveGame` as versioned JSON in `user://save.json` (outside the repo, in Godot's per-project user-data folder), through a temporary file and a rename. A missing file is a fresh profile, and a file that cannot be used is renamed to `.bak` and never deleted. `ProfileSaver` saves on request, every 10 s while dirty, and on close, focus loss and app pause. To reset progress, delete the one file.
- **Tests never touch the real save.** `SaveGame` calls take a path, and tests use a folder inside `res://.godot/save_tests/` that they create and remove. `Main.save_path` defaults to the real file, and an empty string means "do not load or save", so every test that instantiates `main.tscn` sets it (and the pick screen's `pause_tree` to false) before `add_child`.
- **When rewards apply.** Stat and slot rewards apply at once, through `RunProgress` (a Player component that turns collected XP into level-ups). Starting-spell rewards apply at the next run start. `Player.apply_stat_bonuses(StatBonuses, heal_difference)` is the one stat path: it computes speed, maximum health and the spells' mana bonus from the player's base values, so applying twice is harmless (Sprint 9 equipment will feed the same `StatBonuses`). The mana bonus lives on each `SpellInstance` (`max_mana()`), never on a shared `SpellData`, so read a pool through `max_mana()`.
- **Run start.** `Main._begin_progression` loads the profile, rolls every earned random buff (`StartingBuffs.roll_random`) and asks for each earned chosen buff on `BuffPickScreen` (the world is paused meanwhile), into an in-memory `RunBuffs`. **Starting-spell buffs are never saved: they are rolled or picked again at every run start** (player feedback). Then `RunStart.prepare` sets stats, slots, equipment bonuses and the two starting spells (`SpellBuilder.with_buffs` returns a copy with the buffs folded in, so the shared spell resources are never changed). The pool leaves out Additional Base, because a starting spell has no second Base.
- **XP gems and Gold coins.** `EnemyData.xp_reward` and `gold_reward`, one `ValueGem` pickup (kind XP or GOLD, collected by the same `PickupCollector`, which emits `xp_collected` or `gold_collected`) and one `ValueDropper` per kind (capped at 150, merging a new drop into the oldest at the cap so nothing is lost). The XP bar, Gold counter, level toast and the death screen's summary line have the Sprint 13d look.

## Gold and equipment (Sprint 9)

- **Gold** is banked in `PlayerProfile.gold` the moment a coin is collected (`RunProgress.add_gold`) and saved like XP. Dying never costs it.
- **One modifier path.** Level rewards and equipped items both add into one `StatBonuses` (`StatBonuses.combined`), pushed by `Player.apply_stat_bonuses` to speed, health and `SpellLoadout.set_bonuses`. `RunStart.prepare` and `RunProgress._apply` both use level plus `ShopSystem.bonuses`, so a level-up never drops equipment and nothing applies twice. The stats are SPEED, HEALTH, SPELL_MANA, the four element damages, SPELL_DAMAGE, CAST_SPEED and the two chance effects.
- **Casting.** Static `CastMath` holds the formulas (damage scale = spell damage times the mean of the spell's element bonuses, floored at 0.1; interval = base / (1 + casting speed), floored at 0.05 s; pool). `SpellLoadout.try_cast` sets `AreaEffect.damage_scale` on each effect before `launch` (the one multiplication is in `AreaEffect._configure_hitbox`), so no Area and no shared `SpellData` is edited. `SpellInstance` carries `cast_speed_bonus` and `max_mana_bonus` (per instance). Wand "cast twice" launches every shot a second time for the same mana and cooldown, and Staff "double damage" doubles every shot, each rolled once per cast from `SpellLoadout.rng`. `SpellBuilder.describe(spell, bonuses)` and the crafting preview use the same math.
- **Equipment is data:** `EquipmentData` (id, name, description, category, price, `EquipmentModifier` list, colour) in an `EquipmentCatalog` (`resources/equipment/`). Three slots: Robe, Weapon (Wand or Staff) and Headwear (Hat or Hood, identical behaviour). Adding an item is a new `.tres` plus a catalog entry. No code branches on an item id.
- **Shop.** The static `ShopSystem` holds all the rules (`buy` is all-or-nothing and equips into the item's slot, `equip` and `unequip` are free, `bonuses` skips unknown, unowned or misplaced ids). `ShopScreen` is a thin layer over it, opened by the death screen's Shop button, and every successful action is saved at once. Pressing an item buys, equips or takes it off depending on what the player has.
- **Death-screen taps.** Touches never reach buttons (mouse emulation is off), so `DeathScreen.handle_event` handles a tap on the Shop button itself (it requests the shop and never restarts), ignores every restart while the shop is open (`set_shop_open`), and still restarts on a tap anywhere else. This was checked on a real window, not only headless.
- Tests that instantiate `main.tscn` set `save_path` and never touch the real save, as in Sprint 8.

## Potions (Sprint 10)

- **Potions are data:** `PotionData` (id, name, description, price, `kind` HEAL / RESTORE_MANA / TIMED_BONUS / INVULNERABILITY, magnitude, duration, cooldown, `EquipmentModifier`s, colour) in a `PotionCatalog` (`resources/potions/`, bar order). No code branches on a potion id. Adding a potion of an existing kind is a new `.tres` plus a catalog entry.
- **Stock (Sprint 14b: potions last ONE run, user decision).** `RunPotions` (`scripts/potions/`, in memory, never saved) holds at most `MAX_POTIONS` = 3 of each type; `Main` makes a fresh one at every run start, so unused potions are lost when the run ends. The in-run merchant is the only source: the death-screen shop has no Potions row and `PlayerProfile` no longer holds potions. Buying is `ShopSystem.buy_potion(profile, potions, catalog, id, multiplier)` (Gold from the profile, the count and cap from `RunPotions`, all or nothing). A drink saves nothing; a merchant sale saves the Gold spent. An old save's potions load into `PlayerProfile.legacy_potions` (a count above 99 is a bad save), are cashed in at list price by `ShopSystem.cash_in_legacy_potions` at run start, and the save is rewritten without them.
- **Drinking.** Static `PotionSystem` holds the rules: `refusal` returns why a potion can't be drunk (checked in a fixed order: unknown, dead, none left, type cooldown, shared cooldown, effect running, full health, full mana) and `apply` does the effect. A refused potion is never consumed and starts no cooldown. `PotionBelt` (Player component) drinks through it, keeps each type's cooldown and the 1 s shared cooldown, and holds the controller's selection. Cooldowns and effect timers tick in `_process`, so they freeze while the tree is paused.
- **Timed effects.** `ActiveEffects` (Player component) keeps the running TIMED_BONUS and INVULNERABILITY effects and owns the player's temporary bonus layer. Invulnerability also grants the hurtbox a separate window (`HurtboxComponent.grant_invulnerability`) that the per-hit window can neither shorten nor clear.
- **Stat layers.** The Player holds `level_bonuses`, `equipment_bonuses` and `temporary_bonuses`. Each owner sets its own layer (`RunStart` and `RunProgress` the level one, `RunStart` the equipment one, `ActiveEffects` the temporary one) and calls `Player.refresh_bonuses()`, which adds the three, pushes the total through `apply_stat_bonuses` and emits `bonuses_changed`. Nothing else pushes bonuses.
- **Luck** is a `StatBonuses` stat. `DropTable.roll(rng, luck)` multiplies a scroll's weight by `rarity_factor` (Common 1, Uncommon 1 + luck, Rare 1 + 2 x luck, never below 0; falls back to luck 0 if every weight would be zero), and `Main` keeps `ScrollDropper.luck` in step with `bonuses_changed`. At luck 0 the roll is exactly the old one.
- **The potion bar** (`PotionBar`, `PotionSlotWidget`) is a column of six slots at the top right. Slots handle their own touches and left clicks (mouse emulation is off), and `Main` blocks casting until the cast input is released so a click never also fires a spell. Keys Z X C V B N (`potion_1` to `potion_6`), controller X, left stick click and B (`potion_next`, `potion_prev`, `potion_use`; the D-pad is movement, and a test fails if any joypad button belongs to two gameplay actions). A refusal shows its reason in the level toast's message line. The bar hides on death.
- Checked on a real window (3x scale) with a throwaway profile: a tap or a mouse click on a slot drinks exactly once and fires no spell.
